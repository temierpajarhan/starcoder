# AGENT — Mainnet-Only Pendle Flooping (Arbitrum One)

## Цель
Запускать **реальные** (mainnet) попытки “flooping” через Balancer flash-loan → Pendle (mint PY = PT+YT → продать PT → при необходимости докрыть YT) с **автоматическим** подбором параметров до получения положительного профита (**NetProfit > 0**) и фиксации рабочей конфигурации (release candidate).

## Жёсткие правила
- Сеть: **Arbitrum One (chainId 42161)** только.
- **Никаких форков, эмуляторов, callStatic-гейтинга, dry-run симуляций**. Разрешены только **read-запросы** on-chain (view, состояние, котировки, allowance).
- Отправка транзакций — через **приватные релеи/RPC** (если доступны у провайдера) для снижения MEV-риска.
- **GLP/GMX V1** — по умолчанию **заблокированы**. Разрешай только если получишь явный флаг `GLP_OK=1` в конфиге (и всё равно сделай live-проверку статуса).
- Ключи/среда: брать из `.env` (не логировать PRIVATE_KEY). Все артефакты — в `runs/<ts>/`.

## Входные данные
- Адрес **FlashFloopExecutor** (наш контракт-получатель флеш-займа Balancer).
- Адреса **Balancer Vault**, **Pendle Router V3**, адрес **Market** (например, wstETH-market c будущей датой).
- `loanToken` (совместим с SY рынка **без** агрегатора, напр. wstETH для wstETH-рынков).
- Начальный размер `amount`, предел итераций `loopsMax` (по умолчанию 1→2→3), минимальный профит `minProfit` в `loanToken`.
- Ограничители проскальзывания `slippageBps` (например, 50 = 0.5%) для всех обменов внутри флоу.

## Алгоритм (только живые прогоны)
1. **Проверка окружения**
   - Убедись, что в `.env` заданы `ARBITRUM_RPC`, `PRIVATE_KEY`.
   - Проконтролируй chainId=42161 через `eth_chainId`.
   - Верифицируй адреса контрактов (валидные коды на Arbiscan). Не продолжай, если `code == 0x`.

2. **Фильтрация рынков**
   - Если `market` относится к GLP/GMX V1 — остановись, если нет флага `GLP_OK=1`.
   - Иначе продолжай (wstETH/weETH/… с будущей датой экспирации предпочтительны).

3. **Пре-чтения (только view)**
   - `Market.readTokens()` → получи `SY, PT, YT`.
   - Убедись, что `loanToken` совместим (для этой версии агента — “без агрегатора”).
   - Прочитай `decimals`, `symbol` для `loanToken`.
   - Если нужно, проверь allowance на **Pendle Router V3** и **Balancer Vault** и сделай реальные `approve` с небольшим газ-лимитом.

4. **Параметры запуска**
   - Сформируй список канд. параметров:  
     - `loops` ∈ {1, 2, 3} (начинай с 1).  
     - `amount` — геом. сетка от маленького к большому (например, 0.2 → 0.35 → 0.6 → 1.0 единиц `loanToken`).  
     - `slippageBps` ∈ {30, 50, 75}.  
     - `minProfit` стартово небольшой (например, 0.0005 `loanToken`), с возможностью авто-повышения.
   - Для каждой комбинации готовь **реальный** пайплайн: mint PY → sell PT → (если недостаток к возврату+порог) sell YT минимально достаточным объёмом → repay.

5. **Защита от проскальзывания (без симуляций)**
   - Получай **котировки только через view-функции** (например, Pendle Router “approx”/квотеры или специализированные view-эндпойнты), чтобы вычислить **`minOut = quote * (1 - slippageBps/10000)`**.  
   - Если котировка недоступна — используй **консервативный `minOut`** (с запасом), но обязательно **первую попытку** делай с *минимальным* `amount`.

6. **Запуск реальной попытки**
   - Собери `FlashFloopExecutor.execute(Plan)` со списком таргетов/калдаты (Router/Market), `loanAmount=amount`, `minProfit` и `profitRecipient=EOA`.
   - Отправляй **через приватный RPC** (если доступен). Сохраняй tx-hash.
   - Дождись майнинга, зафиксируй **фактические**: вход/выход `loanToken`, остатки в иных токенах (YT), оплаченный газ.

7. **Оценка результата**
   - `NetProfit = Δ(loanToken) + оценка(прочих токенов, если они остались и были выведены) − GasCost`.  
   - Если `< 0` или `< minProfit`:  
     - Уменьши `amount` **или** `loops`.  
     - Увеличь `slippageBps`.  
     - Сменить `market`, если серия неудач (2–3 подряд).  
     - Повтори с шага 4.  
   - Если `≥ minProfit`:  
     - Считай конфигурацию **стабильной** (RC), сохрани в `runs/<ts>/rc.json`, сформируй короткий релиз-репорт.

8. **Политика повторов и остановов**
   - На один рынок — не более `N` неудач подряд (по умолчанию 3), затем смена рынка.  
   - Максимум `M` живых попыток в сессию (по умолчанию 10).  
   - Если за сессию не получен профит — уменьши целевые размеры вдвое и попробуй ещё одну сессию.

## Минимальные команды (пример)
> В репозитории должны быть скрипты `runOnce.ts` и CLI-обёртка. Агент **не** вызывает симуляторы/форки.  
> Он **может** патчить `runOnce.ts`, чтобы проставлять `minOut` из on-chain котировок перед каждой попыткой.

- **Деплой экзекьютора** (однократно): hardhat run scripts/deploy.hardhat.ts --network arbitrum  
- **Живая попытка** (пример):  
  ts-node scripts/runOnce.ts \
  --executor <EXECUTOR> \
  --market <MARKET> \
  --loanToken <TOKEN> \
  --amount 0.35 \
  --loops 1 \
  --minProfit 0.0005 \
  --recipient <EOA>

Перед отправкой агент обязан **обновить** внутри `runOnce.ts` значения `minTokenOut` по всем свопам (PT→loanToken, YT→loanToken) на основе **view-котировок** и `slippageBps`.

## Логи и артефакты
- Каждый запуск: `runs/<timestamp>/run.json` (параметры, адреса, tx-hash, газ, балансы, NetProfit).
- Итог: `runs/<timestamp>/REPORT.md` (таблица попыток, лучшая конфигурация).
- RC: `runs/<timestamp>/rc.json` (market, amount, loops, slippageBps, minProfit, executor, loanToken).

## Безопасность
- Никогда не логируй PRIVATE_KEY.  
- Используй приватные отправки (если провайдер поддерживает).  
- До каждого запуска проверяй, что код по адресам != `0x`.  
- GLP/GMX V1 — запускать **только** при явной разблокировке и ручной проверке статуса.

## Когда завершать
- Как только получен **NetProfit > 0** и подтверждена воспроизводимость (2 успешные попытки подряд) — зафиксируй RC и останавливай подбор.
